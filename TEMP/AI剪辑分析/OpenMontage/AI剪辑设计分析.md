# OpenMontage：AI 剪辑架构分析

## 架构判断

**OpenMontage 的主架构属于分层 Plan-Action，阶段内部可以采用 ReAct。更完整的描述是：预设制作流程下的“规划—执行—评估—返工”架构。**

全局先确定制作方向、预算、素材策略和交付要求，再逐阶段执行；局部则允许 AI 调工具、读取结果、调整方案。它不是纯 ReAct，因为整个任务并非由模型在每一步自由选择方向，而是受阶段、产物和审批约束。

本文的 ReAct 指 Reasoning + Acting，即“推理 → 行动 → 观察结果 → 再推理”，与 React 前端框架无关。

## 判断依据：计划如何控制执行

| 判断点 | OpenMontage 的实际做法 | 架构含义 |
| --- | --- | --- |
| 全局流程 | 选择既有制作管线，按阶段推进 | 提供预设流程骨架 |
| 任务计划 | AI 形成提案、剧本、场景计划和素材需求 | 计划与具体任务相关 |
| 执行动作 | AI 根据阶段计划选择分析、生成、剪辑和合成工具 | 符合 Plan-Action |
| 工具反馈 | 工具返回产物、失败、耗时与成本 | 支持阶段内 ReAct 循环 |
| 计划失效 | 制片人角色可要求修改或退回上游阶段 | 支持重新规划 |
| 推进条件 | 结构校验、阶段状态、人工审批 | 限制自主执行边界 |

与“有一份流程图”不同，这里的规划产物会成为下游执行输入：场景计划决定要生成什么，素材清单决定能剪什么，剪辑决策决定如何合成。

## 两层控制：流程骨架与任务计划

**第一层是预设流程。** 系统规定研究、提案、剧本、场景计划、素材、剪辑、合成和交付等阶段，以及每阶段需要的产物和检查条件。AI 选择适合任务的管线，不能任意跳过制作环节。

**第二层是 AI 生成的具体计划。** 同样一条管线，AI 会根据用户目标决定叙事、镜头、供应商、素材来源和音画安排。后续工具执行围绕这些计划展开。

因此它既不是完全写死的流水线，也不是无边界的自主 Agent：**流程固定，任务决策由 AI 完成。**

## AI 如何完成剪辑

制作前，AI 检查当前可用工具，形成带成本的提案。通过后再写剧本、拆场景、取得素材，并记录实际文件、时长和生成结果。

剪辑阶段读取这些事实，产出剪辑决策清单（EDL）：选择素材与入出点、安排切片顺序、设置速度和层次、配置旁白、字幕、音乐及转场。该阶段主要是规划计算，可以不调用媒体工具。

合成阶段再把 EDL 和素材清单交给执行工具，由选定的引擎完成裁剪、拼接、混音和渲染。**EDL 是 AI 决策与媒体执行之间的合同。**

但这个合同有两种实现路径：

- **模板化合成**：较直接地将结构化剪辑决策转换为成片。
- **定制合成**：AI 还会编写项目专用的合成内容，执行层按入口渲染。此时 EDL 同时承担制作约定和渲染描述，不能说所有画面都只由切片清单决定。

## ReAct 出现在哪里

ReAct 更适合描述阶段内部的操作。例如，AI 先分析素材，发现旁白实际长于场景计划，再决定缩短台词或调整镜头；也可以在生成失败后读取错误，修改参数，重试同一条已批准的制作路径。

这里具备“行动—观察—再决策”的条件，但循环由外部编码助手执行，项目本身并没有实现统一的模型工具循环。是否严格按 ReAct 推理，取决于所使用的助手及其执行方式。

**因此可以确认它支持 ReAct 式局部工作，不能仅凭工具丰富就断言内部实现了专用 ReAct 运行时。**

## 评估与重新规划

普通阶段审查检查结构、完整性和风格约束；制片人角色关注跨阶段问题，例如旁白实际长度与场景计划不符、素材不足、预算逼近上限、音画错位。

发现问题后，可以留在当前阶段修改，也可以退回上游重新规划。后者体现的是 Plan-Action 的重规划能力：**不是不断重试同一个工具，而是判断原计划是否仍然成立。**

这些创作判断主要由技能指令要求 AI 完成。结构校验和阶段审批有程序约束；“内容是否精彩、镜头是否合适”等语义审查仍依赖模型判断。审查协议也允许有限轮次后带警告通过，不能理解成质量问题一定被自动消除。

## 状态和人工控制的边界

阶段产物保存制作事实，检查点保存完成位置、部分进度与历史；AI 因而可以在中断后重新加载必要状态，继续任务。项目文档承担的是外部工作记忆，而不是永久依赖聊天上下文。

人工审批限制阶段推进：需要批准时进入等待，批准后才能正常标记完成。程序会检查审批标记和前置阶段，但它不能独立证明用户真的批准，也不能阻止 Agent 绕过状态工具直接运行媒体命令。因此它是**制作协议内的硬校验，不是执行环境的权限沙箱**。

## 最终定位

**全局：Plan-Action；局部：可用 ReAct；推进方式：评估、审批与必要时重新规划。**

最有价值的是三项分离：

1. 制作流程与具体创作计划分离。
2. 剪辑决策与媒体执行分离。
3. 创作判断与可程序校验的状态约束分离。

它适合端到端视频制作和可恢复的长任务。代价是流程较重，灵活性依赖外部助手遵守制作协议，也不天然具备实时编辑器中人与 AI 同步修改时间线的能力。
