# 粗剪接口文档

当前界面：分镜与粗剪（`StoryboardStage`）。左侧分镜卡/候选素材，右侧 Agent 对话，底部素材架；支持草案、精确匹配、候选采用、生成补镜、批量操作和进入精剪。

## 后端模块

`storyboard.mjs`（`.film/storyboard.json` 的规则与匹配）、`pipeline.mjs`（运行状态）、`pipeline-plan.mjs`（计划结构与校验）、`plan-execute.mjs`（Plan-Execute 编排）、`agent-runtime.mjs`、`agent-flow.mjs`、`agent-chat.mjs`、`agent-tools.mjs`、`semantic-index.mjs`、`asset-descriptions.mjs`。

## 分镜接口

| 接口 | 用途 |
| --- | --- |
| `GET/PUT /api/projects/:id/storyboard` | 读取/整档保存；PUT 带 `baseRevision`，冲突返回 409。 |
| `POST /storyboard/generate` | 从 `text`/`prompt`/`brief` 生成草案。 |
| `POST /storyboard/match` | `{ shotIds?, topK? }`；匹配度是语义分数，跨镜头避免优先复用同一素材。 |
| `POST /storyboard/fill` | `{ shotId, prompt?, duration? }` 生成补镜素材。 |
| `POST /storyboard/apply` | `{ baseRevision, operations }` 应用结构/镜头操作。 |
| `POST /storyboard/handoff` | 把已采用镜头变成粗剪时间线和 `roughcut` 记录；不自动进入最终渲染。 |
| `GET/POST /storyboard/run` | 读取/启动后台 Plan-Execute 粗剪；返回/保存 `run.plan`，`steps` 继续兼容旧页面。 |
| `POST /storyboard/run/cancel`、`/run/retry`、`/run/undo` | 取消计划、从失败步骤继续、撤销 AI 的连续性修改。 |
| `GET/DELETE/POST /agent/chat?scope=storyboard` | 分镜对话历史/清空/ReAct 对话；POST 返回 `reply`、`runId`、`toolCalls`、`changed`、`applied`、`issues`/`question`；兼容旧 `operations`/`proposal`。 |

## 与素材/Agent 有关

- `GET/POST /api/projects/:id/asset-descriptions`：候选缩略图的说明。
- `POST /api/projects/:id/index/search`：素材架的语义检索（`mode:'frame'`）。
- `GET /api/agent-cards`、`GET /api/provider-cards`：判断当前是否有可用的分镜 Agent/provider。
- `GET/PATCH /api/prefs`：`storyboard.candidateCount` 控制候选数量。

## 数据与约定

分镜文档在 `.film/storyboard.json`；`revision` 是并发写基线。`shot.match.confidence` 只表示语义匹配度，视觉复核只写 `review`。匹配工具和用户点击匹配共用同一后端实现；Agent 操作不能直接写文件，必须返回可校验的 operations。交接后编辑阶段不再读取分镜，`storyboard.handedOffAt` 是分界。

Plan-Execute 的计划写入 `.film/roughcut-run.json` 的 `plan` 字段，包含 `goal`、`source`、`planner`、`state`、`replans` 和步骤的 `id/role/action/dependsOn/state/attempts`。planner 不可用时使用默认五阶段计划；失败只重规划剩余步骤，不重放已完成的写入。MCP 的 `match_storyboard`、`fill_storyboard`、`handoff_storyboard`、`validate_storyboard` 与这里共用实现。
