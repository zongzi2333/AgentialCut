# OpenFilm 视频语义化说明

本文说明 OpenFilm 当前如何把视频、图片变成可检索的语义向量，重点说明图片帧的获取规则。实现复用 VideoSeek 的抽帧、Chinese CLIP 编码和语义分镜代码，OpenFilm 只增加目录、catalog、Lance 存储和 HTTP 任务层。

## 1. 总流程

```text
视频/图片
  → 媒体探测（时长、类型）
  → 抽帧（图片只有 1 帧）
  → Chinese CLIP 图像编码
  → 帧向量写入 Lance frames
  → 语义分镜，生成镜头向量写入 Lance chunks
  → 文本/图片查询编码后，在对应向量库做余弦检索
```

只有 `video` 和 `image` 进入画面索引。音频、字幕、网页/页面在首版不进入画面语义索引。

## 2. 视频抽帧规则

### 2.1 采样率

视频帧率不是原视频帧率，而是 OpenFilm 的**抽帧采样率**。

当前规则：

- 如果任务明确提供 `samplingFps`，使用该值。
- 否则由 OpenFilm sidecar 选择：
  - 时长 `<= 600 秒`，或时长探测失败/未知（0）：**2 FPS**
  - 时长 `> 600 秒`：**1 FPS**

也就是：

| 视频时长 | 默认采样率 | 约每帧间隔 |
|---|---:|---:|
| 10 分钟以内 | 2 FPS | 0.5 秒 |
| 超过 10 分钟 | 1 FPS | 1 秒 |
| 时长未知 | 2 FPS | 0.5 秒 |

当前设置界面和 Studio API 还没有暴露 `samplingFps`；使用默认值。侧车内部支持该选项，后续可以作为“抽帧规则”设置开放。

### 2.2 FFmpeg 实际取帧

视频通过 FFmpeg 的 `fps` 滤镜按上述采样率均匀重采样，然后做方形预处理：

```text
fps=<采样率>,
scale=224:224:force_original_aspect_ratio=increase:flags=bicubic,
crop=224:224
```

含义：

- 先按采样率均匀选取帧，不根据镜头切换、运动、画面差异或黑帧检测取帧。
- 等比放大/缩小到短边至少 224 像素。
- 从中心裁成 `224 × 224` 的正方形。
- 输出 BGR 原始帧。
- 当前固定使用 center crop，不使用拉伸。

因此，一个 16:9 视频会被裁掉左右两侧一部分，只保留中心正方形；竖屏视频则裁掉上下部分。

### 2.3 时间戳

抽出的帧按顺序编号，记录时间使用：

```text
frame_time = frame_index / sampling_fps
```

并四舍五入到毫秒。也就是说，时间是基于抽样序号推算的，不是直接读取原始视频每一帧的 PTS。

例如 2 FPS：

```text
第 1 帧  0.0 秒
第 2 帧  0.5 秒
第 3 帧  1.0 秒
```

第一帧从 0 秒开始。抽帧时间用于镜头范围、缩略图和搜索结果的时间定位。

### 2.4 批次与设备

- 编码批大小当前由 VideoSeek 配置 `embedding_batch_size = 8` 控制。
- 图像预处理和 ONNX 推理分开：预处理不在推理锁内，ONNX 推理串行执行。
- 当前 sidecar 默认 `cpu` 设备。
- 支持 GPU 的模型包/运行环境可以走 GPU，但当前设置界面没有设备切换；设备由 sidecar 启动参数 `--prefer-gpu` 和运行环境决定。
- FFmpeg 线程数可通过环境变量 `VIDEOSEEK_FFMPEG_THREADS` 调整；默认 `0`，即由 FFmpeg 自行决定，代码上限为 16。
- Windows 上可以启用实验性 D3D11VA 硬解；失败会回退 CPU。默认关闭。

## 3. 图片规则

图片不做视频抽帧，也不按 FPS 采样：

- 读取原图一次。
- 在编码器内等比缩放到短边 224，再中心裁成 `224 × 224`。
- 生成 **1 个帧向量**，时间记为 `0 ms`。
- 生成 **1 个镜头向量**，范围 `0–0 ms`，帧数为 1。

所以图片在结果中是一个单帧语义单元。

## 4. 图像编码

当前默认模型：`Chinese CLIP ViT-B/16`。

- 图像输入：`224 × 224` BGR。
- 转 RGB，按模型 `preprocessor_config.json` 的 mean/std 归一化。
- ONNX 视觉塔输出 512 维向量。
- 向量做 L2 归一化后写入 Lance。
- 相似度使用余弦相似度。

如果模型包更换，编码维度由模型决定；同一个向量库不能混用不同模型的向量。

## 5. 语义分镜（chunks）

视频的帧向量之外，还会在线构建镜头范围：

- 相邻帧与当前核心帧的余弦相似度低于 `similarityThreshold` 时，考虑切分。
- 允许一帧过渡帧通过“与核心帧均值的相似度”检查，`chunkEdgeThreshold` 默认比主阈值低 0.02。
- 镜头最少 `minChunkSize = 2` 帧，最大 `maxChunkDuration = 90 秒`。
- 少于最少帧数时，当前片段会继续吸收帧，避免产生孤立的过短镜头。
- sidecar 当前把 `minChunkDuration` 设为 0，因此不会按“镜头时长”再做一次后置合并。
- 一个镜头的向量由该镜头内所有帧向量取**中位数**，再 L2 归一化。
- 镜头的时间范围取该片段第一帧到最后一帧的采样时间。

当前默认参数：

```text
similarityThreshold = 0.87
chunkEdgeThreshold  = 0.85
minChunkSize        = 2
maxChunkDuration    = 90 秒
```

这些值目前没有在设置界面暴露；`semantic-index.mjs` 的任务请求也没有把自定义 `options` 透传给 sidecar，因此实际使用 sidecar 默认值。

## 6. 检索

- 文本查询：由同一 Chinese CLIP 文本塔编码。
- 图片查询：由图像塔编码。
- 默认按镜头（chunk）检索，也可以按帧（frame）检索。
- 在**同一个向量库内**做余弦近邻搜索；不同模型/不同维度的库不混算。
- 多个库分别检索后，Studio 再融合排名。
- 只返回 `ready` 且未被排除、未丢失的素材。

## 7. 当前可调与不可调

| 项目 | 当前值/方式 | 是否有 UI |
|---|---|---|
| 抽帧采样率 | 默认 2 FPS（≤10 分钟），1 FPS（>10 分钟） | 否 |
| 方形预处理 | 224×224，center crop | 否 |
| 编码批大小 | 8 | 否 |
| ONNX 设备 | 默认 CPU；启动参数可改 | 否 |
| FFmpeg 线程 | 环境变量，默认自动 | 否 |
| 硬解 | 默认 CPU；实验性 D3D11VA | 否 |
| 分镜阈值 | 0.87 / 0.85 / 2 帧 / 90 秒 | 否 |
| 模型 | Chinese CLIP ViT-B/16 | 可在模型页查看/导入 |

后续如果要开放这些参数，建议增加一个“索引参数”面板，并把参数写入**新向量库的 meta**，不要对已有向量库原地修改；参数变化应创建新库，避免旧向量和新规则混用。

## 8. 已知影响

- 2 FPS 对快速剪辑可能漏掉很短的镜头。
- 固定中心裁切会忽略画面边缘的内容。
- 抽帧时间来自采样序号，不是原始 PTS；对可变帧率视频，时间可能和原视频帧时刻有细小偏差。
- 不做黑帧过滤、重复帧去重和场景切换检测。
- 首版只做画面语义，不含台词、字幕、音频事件或 OCR。
