# OpenFilm 素材库语义索引设计

状态：定稿  
范围：项目素材库 + 外部素材库；一期只做画面语义检索  
默认编码器：Chinese CLIP base（本地 ONNX）  
实现路线：Python sidecar 复用 VideoSeek 的索引/检索内核，不重写索引内核

---

## 1. 术语

### 1.1 素材库

一组源文件：

- 项目库：项目文件夹。
- 外部库：用户添加的外部文件夹，只读。

### 1.2 向量库（索引空间）

一个向量库只关联**一个编码模型**，包含该模型生成的帧向量、镜头向量和索引元数据。

- 模型、模型版本、维度、预处理、采样率、分镜算法版本任一变化，就是一个新的向量库。
- 同一个素材库可以有多套向量库，但每套只属于一个模型。
- 不同向量库的向量不能混合比较。
- 一个素材库按引擎保存默认向量库；画面引擎一期只有一个默认向量库。

### 1.3 编码器

编码器通过统一接口接入：

- `local-onnx`：本地模型包，ONNX Runtime 推理。
- `remote-http`：供应商 API，返回向量。

画面检索要求同一模型的**图像编码**和**文本编码**同时可用。只有文本 embedding 的远程服务不能单独构成画面向量库。

远程编码只上传抽帧图片，不上传源视频；默认关闭，启用时必须明确同意。API Key 由 Studio 的 Provider 设置提供，sidecar 只在任务内存中使用，不写入索引目录。

### 1.4 多库、多模型搜索

- 每个素材库有自己的默认向量库和模型。
- 搜索多个库时，按向量库分组，各自用对应模型编码查询、独立检索。
- 不同模型的结果按排名融合（RRF），不比较原始相似度。
- 结果携带 `libraryId`、`storeId`、`modelId`、`providerId`。

## 2. 总体架构

```text
Studio UI
  素材库页 / 索引面板 / 搜索结果 / 设置
        │
        │ /api/index/*
Studio Server
  IndexService
   ├─ sidecar 生命周期 / 健康检查
   ├─ 项目库与外部库注册
   ├─ 媒体根目录 / 索引目录权限
   ├─ 凭据与事件
   └─ IndexDriver
        │
        │ 127.0.0.1 + Bearer token
语义索引 sidecar（Python，复用 VideoSeek）
  JobRunner / Catalog / EncoderRegistry
  FrameExtractor / Chunker / VectorStore
  QueryEngine / Provider adapters
        │
        ├─ 本地 ONNX 模型
        └─ 远程编码 API
```

### 2.1 Studio Server

- 启动、停止、重启 sidecar。
- 把项目库/外部库的**媒体根目录**和**索引目录**注册给 sidecar。
- 代理索引任务、搜索、状态和事件。
- 把 UI 的相对路径、素材与 sidecar 的库、向量库、内容键对应起来。
- 保存模型包路径、默认向量库、远程 provider 设置。
- 不把索引数据写入 Studio Home。

### 2.2 sidecar

- 文件对账、抽帧、编码、分镜、向量写入。
- 任务队列、取消、进度、失败重试。
- 向量检索、查询计划、重排/融合、时间聚合。
- 本地/远程编码器适配。
- 只读媒体文件；只写索引目录和临时目录。

## 3. 存储布局

### 3.1 项目库

```text
<project>/
  .film/
    index/
      catalog.sqlite
      stores/
        <storeId>/
          meta.json
          frames.lance
          chunks.lance
      tmp/
```

- `catalog.sqlite`：内容、位置、向量库、任务、排除状态。
- `stores/<storeId>/`：一个向量库，只属于一个模型。
- `meta.json`：模型、provider、版本、维度、预处理、采样、分镜版本。
- `tmp/`：抽帧临时文件，任务结束清理。
- `.film/index` 位于项目目录内；项目移动/复制时索引随之移动。
- `.film` 已被项目 git 忽略，不进入版本历史。
- 索引不进入项目导出。

### 3.2 外部库

默认：

```text
<external-library>/.openfilm/index/
```

结构与项目库一致。

- 外部库可写时，索引放在外部库内。
- 外部库只读或没有写权限时，注册库时要求选择该库的索引目录，路径记录在 Studio 设置中。
- 外部库的索引目录同样不放在 C: 用户目录，除非用户自己选择那里。
- 外部库离线时，索引仍保留；搜索标记离线，不崩溃。

### 3.3 模型包

模型包是跨库共享的，不复制到每个项目。

- 首次导入 zip 时选择模型目录 `modelsRoot`，记住路径。
- `modelsRoot` 不默认写入 C: 用户目录；默认选择与项目库同一磁盘。
- 模型包目录只存模型文件，不存项目素材或向量。
- 删除项目不会删除共享模型包。

### 3.4 临时文件

- 抽帧临时文件放在索引目录的 `tmp/` 下。
- 任务结束或启动恢复时清理。
- 不把抽帧图片长期保存。

## 4. 数据模型

### 4.1 表

| 表 | 关键字段 | 说明 |
|---|---|---|
| `libraries` | `id`, `kind`, `media_root`, `index_root`, `name` | 项目库/外部库 |
| `contents` | `key`, `size`, `duration_ms`, `width`, `height`, `kind` | 内容指纹 |
| `locations` | `library_id`, `rel_path`, `content_key`, `mtime_ns`, `excluded` | 文件位置 |
| `stores` | `id`, `library_id`, `engine`, `provider_id`, `model_id`, `model_version`, `dimension`, `preprocess`, `sampling`, `chunk_version`, `state` | 向量库，一条记录一个模型 |
| `units` | `store_id`, `content_key`, `kind`, `start_ms`, `end_ms`, `frame_index` | 帧/镜头单元 |
| `jobs` | `id`, `library_id`, `store_id`, `mode`, `state`, `progress`, `error` | 索引任务 |
| `job_items` | `job_id`, `content_key`, `state`, `error` | 单素材进度 |
| `models` | `id`, `provider_id`, `model_id`, `version`, `dimension`, `languages`, `license`, `sha256`, `path` | 本地模型/远程模型描述 |

### 4.2 内容指纹

`content_key = sha256(size + 文件头 10MB + 文件尾 1MB)`

- 只修改 mtime 时，内容键不变，向量复用。
- 重命名/移动只更新 `locations`。
- 文件中部变化但头尾/大小不变的极端情况，使用 mtime 触发重算；保留可选全量哈希字段。
- 同一文件在项目库和外部库各自索引，不跨库共享向量文件。

### 4.3 排除状态

“从素材库移除”不删除文件，在 `locations.excluded` 记录。

- 搜索排除 `excluded=1`。
- 恢复后清除标记。
- 排除状态随项目索引目录保存，不依赖浏览器 localStorage。

## 5. 向量库与模型

### 5.1 向量库标识

```text
storeId = hash(providerId, modelId, modelVersion, dimension,
               preprocessVersion, samplingVersion, chunkVersion)
```

- 一个 `storeId` 对应一个模型和一套参数。
- 不做“一个向量库多模型”。
- 画面向量库拆成两层：
  - `frames`：模型 + 预处理 + 采样。
  - `chunks`：frames + 分镜算法版本。
- 只改分镜参数时复用帧向量，重建 chunks。
- 改采样时重建 frames + chunks。
- 换模型时新建向量库。

### 5.2 默认向量库

- 每个素材库按引擎保存一个默认 `storeId`。
- 换模型时创建新向量库；新库就绪前，旧库继续服务。
- 新库完成后切换默认；旧库保留一套用于回滚，之后按清理策略删除。
- UI 显示每个库的默认模型和全部向量库列表。

### 5.3 本地模型包

- 只通过 zip 导入，不静默下载。
- zip 必须包含 `model_manifest.json`：
  - `id`, `provider`, `variant`, `dimension`, `imageSize`, `languages`
  - `embeddingSpace`, `preprocess`, `files`, `sha256`, `license`, `displayName`
- 导入时校验文件存在、维度、校验和、许可证。
- 默认模型：Chinese CLIP base。
- 模型文件存放在 `modelsRoot`，不复制到每个项目。

### 5.4 远程模型

远程 provider 用 descriptor 登记：

```ts
interface RemoteModel {
  id: string;
  providerId: string;
  modelId: string;
  modelVersion: string;
  dimension: number;
  languages: string[];
  capabilities: { text: boolean; image: boolean; video?: boolean };
  maxBatch: number;
  maxImageBytes?: number;
  license?: string;
}
```

- 只允许同一模型的文本塔和图像塔组成画面向量库。
- 远程模型版本变化时创建新向量库，不覆盖旧向量。
- 远程 provider 的限流、超时、重试、批量由 sidecar 适配。
- 远程编码失败不产生半成品向量。
- 远程编码需要用户明确同意，并记录在库设置中。

### 5.5 与 VideoSeek 的复用

- sidecar 复用 VideoSeek 的索引/检索代码：
  - 抽帧与动态采样
  - ONNX 编码
  - 语义分镜
  - Lance frames/chunks
  - 搜索、时间扩展、重排
- 去掉 PySide6/桌面 UI，只保留服务层，暴露本地 HTTP。
- 参考参数：
  - 采样：前 10 分钟 2 fps，之后 1 fps。
  - 分镜：相似度 0.87、边缘 0.85、最少 2 帧、最长 90 秒。
  - 编码：224×224，归一化，cosine。
  - 解码 2 worker，编码单锁，批量 16。

## 6. 索引流程

### 6.1 手动触发

导入文件不会自动编码。触发方式：

- 索引面板：建立索引 / 更新变更 / 重建。
- 素材详情：索引此素材。
- 卡片或文件夹右键：索引选中项 / 当前文件夹。
- 库设置：索引整个库。

任务模式：

- `new`：只处理未索引素材。
- `update`：未索引 + 待更新，复用未变化内容。
- `rebuild`：强制重算指定向量库。

### 6.2 步骤

1. 对账：`stat` 检查新增、变更、丢失；不自动编码。
2. 计划：按内容键和参数查找可复用向量，列出需要处理的素材。
3. 抽帧：FFmpeg 动态采样，输出 224×224；图片作为单帧；音频和页面在画面引擎中跳过。
4. 编码：本地 ONNX 或远程 provider；校验维度并归一化。
5. 分镜：在线构建语义镜头；镜头向量为帧向量均值。
6. 提交：每个素材原子写入；失败不影响其他素材。
7. 收尾：更新状态、清理临时帧、记录失败；任务期间文件变化则标记 stale。

### 6.3 状态

- `not-indexed`：未索引，搜索不返回。
- `indexing`：索引中，只搜索已就绪部分。
- `ready`：可搜索。
- `stale`：文件已变化，搜索不返回旧结果。
- `partial`：部分素材失败，成功部分可搜索。
- `error`：任务失败，保留已完成部分。
- `missing`：源文件丢失或外部库离线，搜索排除。

文件变化只标记 stale，不自动重编码。删除/隐藏只更新排除状态。

### 6.4 并发与限制

- 全局同一时间一个索引任务；其余排队。
- 抽帧 1–2 并发；编码串行或单会话；远程按限流。
- 取消在帧/批次边界生效，kill FFmpeg，已提交素材保留。
- 开始前检查索引目录磁盘空间。
- 远程编码记录上传帧数、耗时、失败。

## 7. 检索流程

```text
请求
 → 选择库/向量库
 → 按向量库分组
 → 各向量库用对应模型编码查询
 → 向量检索
 → 时间扩展/合并/去重
 → 跨向量库 RRF
 → 映射回素材
```

### 7.1 查询

- 文本：自然语言描述。
- 图片：粘贴、上传、拖入；一期使用全图，不裁剪。
- 向量：调试或后续预设使用，不作为普通 UI 功能。

### 7.2 模式

- `chunk`：语义镜头，默认。
- `frame`：精确时刻；命中后前后扩约 3 秒并合并重叠。
- `group`：按素材保留最佳命中。
- `topK`：默认 100，最大 500。
- `minScore`：由模型元数据提供默认值，可调整。

### 7.3 多库多模型

- 每个库使用自己的默认向量库和模型。
- 搜索“全部库”时按 `storeId` 分组，分别编码、检索。
- 不同模型的原始分数不可比较；合并时使用 RRF。
- 结果携带 `libraryId`、`storeId`、`modelId`、`providerId`。
- 某向量库缺少文本或图像编码能力时跳过并返回说明。

### 7.4 结果

```ts
interface SearchHit {
  libraryId: string;
  storeId: string;
  modelId: string;
  providerId: string;
  contentKey: string;
  assetId: string;
  path: string;
  name: string;
  startMs: number;
  endMs: number;
  anchorMs: number;
  score: number;
  rankScore?: number;
  engine: 'visual';
  thumbUrl?: string;
  degraded?: string;
}
```

`meta`：`returned`, `elapsedMs`, `mode`, `storeIds`, `modelIds`, `indexState`, `degraded`。

### 7.5 查询接口

```ts
interface QueryPlanner {
  plan(request: SearchRequest, context: QueryContext): Promise<QueryPlan>;
}

interface Reranker {
  rank(query: QueryPlan, candidates: ScoredUnit[], context: QueryContext): Promise<ScoredUnit[]>;
}

interface VectorStore {
  ensure(store: StoreMeta): Promise<void>;
  upsert(storeId: string, units: UnitVector[]): Promise<void>;
  delete(storeId: string, filter: UnitFilter): Promise<void>;
  search(storeId: string, vector: Float32Array, filter: UnitFilter, topK: number): Promise<ScoredUnit[]>;
  stats(storeId: string): Promise<CollectionStats>;
}

interface EncoderProvider {
  descriptor: EncoderDescriptor;
  encodeText(text: string): Promise<Float32Array>;
  encodeImages(images: ImageInput[]): Promise<Float32Array[]>;
}
```

一期实现：

- 单查询、单向量库内精确 cosine。
- 多向量库按 RRF 融合。
- `QueryPlanner` 使用规则实现；`Reranker` 使用时间扩展和邻居重排。
- 查询扩展、LLM 重排、跨编码器重排保留接口，不在本期实现。

## 8. 页面交互

### 8.1 搜索区

- `文件`：保持文件名搜索。
- `画面`：启用；文字 + 图片查询；Enter 触发语义搜索。
- 台词、标签入口不显示；本期不实现。

### 8.2 库选择

- 项目库 + 外部库。
- 每个库显示默认模型和索引状态。
- `全部库`：按向量库分组检索并 RRF 融合。
- 外部库可添加、移除注册；不移动/删除源文件。

### 8.3 结果区

- 镜头结果：缩略图、时间码、时长、相似度、素材名、库名、模型徽标。
- 支持多选、按镜头/按素材分组、相关度/时间/名称排序。
- 选中后右侧详情：
  - 视频预览定位到 `anchorMs`
  - 起止时间
  - 分数
  - 来源
  - `加入素材篮`（带 start/end）
  - `定位源文件`
  - `复制时间码`
- 本期不做“在剪辑中使用”和时间线对接；只保留回调接口。

### 8.4 索引面板

- 库切换。
- 默认向量库/模型/provider/维度。
- 已索引、未索引、待更新、失败数量。
- `建立索引`、`更新变更`、`重建`、`取消`、`删除索引`。
- 范围：全部 / 当前文件夹 / 选中素材。
- 进度、当前文件、预计剩余时间、失败列表。
- 索引目录、磁盘占用、清理。
- 新建/切换向量库：新库独立，旧库保留至新库就绪。

### 8.5 设置

- 本地 sidecar 随 Studio 启动。
- 模型目录 `modelsRoot`（首次导入 zip 时选择）。
- 采样率、分镜参数。
- 模型包导入/删除/校验/许可证。
- 远程 provider：地址、密钥来源、批量、限流、隐私同意。
- 日志和诊断。

### 8.6 移除素材

- “从素材库移除”只设置 `excluded`，不操作文件。
- 语义搜索排除被移除素材。
- 恢复后重新参与搜索。

## 10. 状态与错误

| 场景 | UI | 搜索 |
|---|---|---|
| sidecar 未启动 | 索引不可用 | 画面模式禁用 |
| 模型未导入 | 缺少模型 | 禁用，提示导入 zip |
| 未建立索引 | 未索引 | 空态，引导建立索引 |
| 索引中 | 索引中 N% | 只搜已就绪部分 |
| 可搜索 | 可搜索 | 正常 |
| 待更新 | N 个待更新 | 只搜 ready 部分 |
| 部分失败 | 部分失败 | 搜 ready，失败可重试 |
| 索引出错 | 出错 | 可用旧向量或禁用 |

错误码：

- `INDEX_NOT_INSTALLED` 503
- `MODEL_MISSING` 409
- `INDEX_BUSY` 409
- `STORE_NOT_READY` 409
- `UNSUPPORTED_MEDIA` 422
- `PROVIDER_FAILED` 502
- `REMOTE_CONSENT_REQUIRED` 403
- `DISK_FULL` 507

GPU OOM 自动回退 CPU；远程限流退避重试；取消不产生半成品；重启恢复未完成任务的状态。

## 11. 性能与可靠性

- 1 小时视频、1 fps、512 维：约 7.2 MB 帧向量；1000 小时约 7 GB。
- 一期精确 cosine；向量数超过阈值后启用 ANN，再做精确重排。
- 不保存抽帧图片，只保存向量；缩略图按需生成。
- 每个素材原子提交；SQLite WAL；Lance 版本/事务；任务日志。
- 启动时对账，清理临时文件和中断任务。
- 索引目录随项目移动/复制，可在同机复用；模型或路径不匹配时标记 stale。
- 外部库离线时索引保留，搜索排除并提示。
- 删除索引只删派生数据，不删素材和模型包。

## 13. 验收标准

1. 项目库导入视频，建立索引，中文/英文文本查询命中正确时间点。
2. 图片查询可用，结果带时间范围。
3. 取消任务不留下半成品；重启后状态正确。
4. 修改文件后标记 stale，搜索不返回旧结果。
5. 外部库可索引、可搜索；目录离线或只读时行为正确。
6. 多个库使用不同模型时，分别检索并 RRF 融合，不混向量。
7. 换模型创建新向量库，旧库在新库就绪前仍可搜索。
8. 删除索引不删素材；移除素材后搜索不返回。
9. 索引目录位于项目/外部库目录内；模型包使用共享目录。
10. 只搜索已建立索引且 ready 的部分。
