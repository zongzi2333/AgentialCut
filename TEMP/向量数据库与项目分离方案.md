# 向量数据库与项目分离方案

状态：方案草案，尚未实施。  
目标：把向量库、Lance 表、索引 catalog 从项目目录 `.film/index/` 中移出，项目和素材仍可独立移动、复制、备份，索引由 Studio 统一管理。

## 1. 当前实现

现在每个项目库的索引在项目目录内：

```text
<project>/
  film.html
  assets/
  .film/
    index/
      catalog.sqlite
      stores/
        <storeId>/
          meta.json
          frames.lance
          chunks.lance
```

外部库在当前素材目录内：

```text
<external>/.openfilm/index/
```

关键代码：

- `studio/server/semantic-index.mjs`
  - `projectLibrary()` 使用 `project.path/.film/index`。
  - 项目移动/删除前需要注销 sidecar 库，否则 Windows 会因 `catalog.sqlite` 文件句柄导致移动失败。
- `studio/index-sidecar/server.py`
  - `Library` 同时保存 `media_root` 和 `index_root`。
  - 每个库一个 `catalog.sqlite`，向量表在 `stores/<storeId>/{frames,chunks}.lance`。
- 项目稳定标识位于 `<project>/.film/id`，项目改名或移动不改变该 id。

当前方案的代价：

- 项目文件夹移动、复制、备份都会带上大体积索引。
- 项目与索引共享目录，删除/移动项目时容易遇到文件句柄问题。
- 项目导出默认会包含向量数据，分享给另一台机器时通常没有意义。
- 多个项目无法共用一个可配置的索引盘。

## 2. 目标布局

推荐使用“统一索引根目录 + 按库命名空间”：

```text
<indexRoot>/
  libraries/
    <libraryId>/
      catalog.sqlite
      meta.json
      stores/
        <storeId>/
          meta.json
          frames.lance
          chunks.lance
```

- `libraryId`
  - 项目库：项目的稳定 id，来自 `<project>/.film/id`。
  - 外部库：现有 `ext_<sha1>` id。
- 索引目录不再位于项目目录内部。
- `mediaRoot` 只指向素材目录；项目移动、改名只更新 `mediaRoot`，不移动向量。
- 每个库仍然是独立 catalog、独立 stores，沿用现有 sidecar 的多库隔离逻辑。

### 默认索引根目录

建议在设置中增加“索引存储位置”，默认与项目库同一磁盘，例如：

```text
<projectsFolder>/.openfilm-index/
```

如果用户已有独立磁盘，可改成例如：

```text
D:\OpenFilm\Index\
```

不默认写入 `C:\Users\...`；不在模型包目录内存放向量。

## 3. 生命周期

### 3.1 注册项目

项目第一次建索引时，由 Studio 读取 `<project>/.film/id`，在 `<indexRoot>/libraries/<id>/` 注册库。

素材目录只作为 `mediaRoot` 传给 sidecar。项目目录中不再创建 `.film/index/`。

如果 `.film/id` 不存在，按现有项目打开逻辑先创建 id，再注册。

### 3.2 项目移动、改名

- 改名：id 不变，索引目录不变，只更新 `mediaRoot`。
- 移动项目文件夹：索引目录不变；重新对账 `mediaRoot`，必要时把旧路径的库注销后按新路径注册。
- 项目复制：
  - 复制项目文件夹会连同 `.film/id` 复制过去；现有逻辑会给副本分配新 id。
  - 新 id 使用新的索引命名空间，不共享原项目的向量。
  - 复制后需要重新建索引。

### 3.3 项目删除

建议默认把 `<indexRoot>/libraries/<id>/` 移到系统回收站，而不是直接永久删除；这样与项目文件夹的删除行为一致。

也可以保留一个可配置的“保留 N 天”策略，但第一版建议直接随项目删除。

### 3.4 外部库

外部库的媒体目录只读；索引目录统一放在 `<indexRoot>/libraries/<extId>/`。

外部库注册信息（名称、mediaRoot、indexRoot）仍放在 Studio 自己的注册表里，不写到素材目录。

## 4. 一次性迁移现有索引

为已有 `.film/index/` 提供迁移工具：

1. 暂停新索引任务；等待当前任务结束。
2. 关闭需要移动的项目库 sidecar 连接。
3. 关闭相关 watcher，避免 Windows 文件句柄。
4. 对每个项目：
   - 读取项目 id。
   - 在 `<indexRoot>/libraries/<id>/` 创建临时目录。
   - 复制 `catalog.sqlite` 和 `stores/` 到临时目录。
   - 校验 SQLite 可打开、Lance 表可读。
   - 原子改名为正式目录。
   - 更新注册表。
5. 校验成功后再处理项目内旧的 `.film/index/`：
   - 第一版建议保留一个迁移标记或把旧目录移到回收站，不直接永久删除。
6. 外部库按同样方式迁移自己的索引目录。
7. 迁移失败的项目保持原状，并在设置中列出，可重试。

迁移必须支持回滚：新目录未验证成功前，不能删除旧目录。

## 5. 代码修改点

### 5.1 Studio Server

- `semantic-index.mjs`
  - 新增 `indexRoot()` 配置读取。
  - `projectLibrary()` 改为：

    ```text
    <indexRoot>/libraries/<project.id>
    ```

  - 项目移动后只更新 `mediaRoot`。
  - 删除项目时同时把对应索引目录移入回收站。
  - `index-libraries.json` 继续保存外部库注册信息；项目库可由项目列表和 `.film/id` 推导。
- `server.mjs`
  - `POST /api/index/roots` 或设置接口：选择/校验索引根目录。
  - 迁移接口：`POST /api/index/migrate`（后台任务）。
  - 项目删除/移动流程保留现有 sidecar 注销和 watcher 关闭逻辑。

### 5.2 Sidecar

- `Library` 继续接收独立的 `media_root` 和 `index_root`，现有结构已经适合这种分离。
- 新增启动时扫描 `<indexRoot>/libraries/*`，加载库注册信息。
- 项目库和外部库的 catalog 互不影响。
- 当前 `DELETE /v1/libraries/:id` 已能关闭 catalog；迁移时直接复用。

### 5.3 设置界面

- 在“通用”或“向量库”中加入“索引存储位置”：
  - 当前路径；
  - 磁盘剩余空间；
  - 更改位置；
  - 迁移已有索引。
- 向量库卡片显示实际 `indexRoot`，不再显示项目内 `.film/index`。
- 设置中显示迁移进度、失败项目、可重试。

### 5.4 API 返回

`SemanticLibrary` 增加或明确：

```text
indexRoot      统一索引根下的库目录
mediaRoot      素材目录
catalogPath    catalog.sqlite 的绝对路径
```

现有 UI 的存储位置展示直接使用这些字段。

## 6. 备份、导出与分享

- 项目导出默认不再包含向量库，只导出影片、素材、字幕和版本历史。
- 需要带走索引时，提供单独的“导出向量库”压缩包。
- 另一台机器导入项目后，如果没有索引，需要按当前模型重新建索引。
- 模型包仍在共享模型目录，不随项目导出。

## 7. 风险与约束

- 项目 id 是唯一关联键，不能用文件夹名或相对路径作为长期主键。
- 索引根目录不能放在模型包目录中。
- 迁移时必须关闭 sidecar catalog 和文件 watcher，这是当前 Windows 迁移失败的直接原因。
- 索引目录和项目库如果位于不同磁盘，项目移动不再需要移动向量；这是收益，但需要保证索引盘可用。
- 项目删除后的索引清理需要防止误删共享库。
- 如果多台 Studio 共用同一个索引根，需要额外的锁和实例标识；第一版建议只支持单机单 Studio。

## 8. 分阶段实施

1. 增加统一 `indexRoot` 配置和目录布局，但先不自动迁移。
2. 新项目直接使用统一索引根；旧项目继续读 `.film/index`。
3. 设置页加入“迁移现有索引”，完成后旧目录可回收。
4. 删除项目时清理对应索引；增加孤儿索引扫描。
5. 最后再移除项目内 `.film/index` 兼容逻辑。

## 9. 需要确认的问题

1. 统一索引根默认放在项目库旁边的 `.openfilm-index`，还是放在用户单独选择的目录？
2. 删除项目时，索引目录是直接进回收站，还是保留一段时间？
3. 是否需要支持多台机器或多个 Studio 实例共享同一个索引根？
4. 外部库的索引也统一放到中央索引根，还是保留“外部库目录内可自定义”的现有能力？
5. 项目导出是否需要提供“连同向量库一起导出”的可选开关？
