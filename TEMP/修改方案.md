# Agent ReAct 与多 Agent Plan-Execute 修改方案

> 本轮只做设计，不修改代码。目标是把当前“一次性 JSON 操作”升级为：对话 Agent 用 ReAct，粗剪用 Plan-Execute 协调多个专业 Agent；保持现有页面结构、5 个流水线阶段 ID 和“无审批门、Agent 不渲染/不导出”的约束。

## 1. 目标边界

- 对话 ReAct：`scope=storyboard` 使用 `storyboard` Agent，`scope=edit` 使用 `conversation` Agent；两者都能连续调用工具、读取结果、修正并验收。
- 粗剪流水线：`planner` 生成计划，编排器调度 `storyboard`、`material`、`edit`、`qc` 按依赖执行；失败可重规划。新增 `planner` 工作槽，其余六个角色保留。
- 所有 Agent 共用一套 `ToolRegistry`，不允许“内置 Agent 一套、MCP 一套、UI 一套”。
- 工具结果必须返回“实际改变了什么”，不能只返回自然语言。
- 不新增最终审批门；每一步成功后保存检查点，失败保留已完成步骤；连续性修改保留撤销快照。
- 不暴露 render、export、最终发布工具；TTS/配乐仍按音频阶段边界处理。
- 页面布局不改，只增加 Agent 运行状态/计划/工具进度的数据与展示位。

## 2. 当前差距

1. `callAgent()` 只发消息，不接收工具定义；`agent-cards.tools` 目前只是配置，不参与运行。
2. `conversationTurn()` 每次只调用一次模型，返回 `operations`/`filmOps`；没有“工具调用—结果—再推理”的循环。
3. 对话 Agent 没有 `read_project`、`read_storyboard`、`read_timeline`、`search_materials`、`qc`、`preview`、`undo` 等可调用工具。
4. 粗剪流水线是固定五步，模型 Agent 之间没有显式计划、依赖、验收和重规划。
5. 外部 MCP 原有 10 个工具；现已补上 `match_storyboard`、`fill_storyboard`、`handoff_storyboard`、`validate_storyboard`，其余读取/字幕/抽帧/工件工具仍在目标清单中。
6. 工具结果没有差分和验收；模型可能口头成功，但工程没有变化。
7. 长对话只带最近 12 条消息，没有压缩/检查点；复杂任务容易丢失上下文。

## 3. 统一工具层

### 3.1 工具注册表

把现有 `agent-tools.mjs` 扩展为唯一工具注册表。每个工具声明：

```ts
type ToolDefinition = {
  name: string
  category: 'read' | 'search' | 'write' | 'generate' | 'verify' | 'preview' | 'plan' | 'interact'
  roles: AgentRole[]          // 哪些 Agent 可调用
  phases: ('storyboard' | 'edit')[]
  write: boolean
  inputSchema: unknown
  run: (ctx, args) => Promise<ToolResult>
}
```

`ToolResult` 至少包含：

```ts
type ToolResult = {
  ok: boolean
  data?: unknown
  changed?: { storyboard?: boolean; timeline?: boolean; clips?: string[]; shots?: string[] }
  rev?: string | number
  issues?: string[]
  error?: string
}
```

大结果（整份分镜、全量时间线、帧列表）不直接塞回上下文，返回摘要和引用；需要时通过 `read_artifact` 分页读取。参考帧/抽帧结果以多模态内容返回，不能只给文件路径。

### 3.2 执行策略

- `read` / `search` / `verify`：可并行，幂等。
- `write`：串行执行；执行前记录快照，执行后返回差分。
- `generate`：单独标记费用/耗时；本轮不把图像/视频/TTS/音乐生成纳入默认对话权限。`fill_storyboard` 是显式生成动作；搜索由 `match_storyboard` 先完成。
- 工具失败：不提交该工具所在草稿，错误返回给模型；模型可以修正后重试。
- 同一轮相同工具、相同参数的结果可复用，避免重复读/重复分析。

### 3.3 运行检查点

当前实现按步骤保存检查点，而不是再引入一套草稿文件模型：

- 每个步骤先读当前文档，成功后用 `saveStoryboard` 带 revision 保存；
- 失败保留已经完成的步骤，运行记录标明失败步骤；重试只重跑未完成步骤；
- 连续性修改额外写 `.film/roughcut-undo.json`，页面可撤销；
- 时间线工具保留 `.film/agent-undo.json` 快照；
- 不引入用户审批卡。

这保持了原项目的文档结构和 revision 冲突语义，也避免制造第二套工程格式。

### 3.4 项目级 Agent 工作区

每个项目有独立工作区 `.film/agent-workspace/`，内置 Agent 按角色分目录，外部 MCP Agent 使用 `shared/`。

- 工具：`workspace_list`、`workspace_read`、`workspace_write`、`run_code`。
- 代码只支持 Node.js/Python，在工作区目录执行，不提供 shell 命令字符串。
- 默认超时 10 秒、最大 30 秒；输出上限 64KB；路径不能离开工作区，也不能跟随符号链接。
- 运行环境只给 `OPENFILM_PROJECT`、`OPENFILM_WORKSPACE`、`OPENFILM_AGENT_ROLE` 和系统必要变量，不注入 provider key。
- 工作区是项目的一部分，随项目移动/删除；它不是安全沙箱，不能绕过分镜/时间线工具或渲染/导出限制。

## 4. 对话 Agent：ReAct

### 4.1 循环

```text
用户消息
  → 组装上下文、历史、工具目录
  → 模型输出文本或 tool call
  → 执行工具（读工具可并行，写工具串行）
  → 把 ToolResult / changed / issues 追加到消息历史
  → 继续模型，直到没有 tool call
  → 修改过文档则执行一次验收/QC
  → 提交草稿，返回 reply + changed + rev
```

默认最多 8 个工具回合；用户可停止。超过预算返回“未完成”并保留草稿，不伪造完成。缺少关键信息时模型可以调用 `ask_user` 暂停循环，前端显示问题并回传答案；这不是审批门，不改变已确定的计划。

### 4.2 工具调用协议

优先使用 provider 原生 tool calling；对不支持原生工具调用的 provider，使用同一套 JSON 动作协议：

```json
{ "tool": "search_materials", "arguments": { "query": "雨夜街道", "topK": 12 } }
```

两条路径都进入同一个 `ToolRegistry`，不能出现第二套实现。

### 4.3 分镜/剪辑阶段

- `scope=storyboard`：可用读取、检索、匹配、补镜、编辑分镜、撤销、QC、预览；补镜生成是单独的显式动作，不写时间线。
- `scope=edit`：可用读取项目/时间线/文件、检索素材、编辑时间线、QC、预览、撤销；交接后不读/不分镜。
- 写入在草稿上执行；一轮结束自动提交，返回 `applied`、`rev`、`changed`。页面收到 `applied:true` 时不能再调用旧的分镜 apply，避免二次应用。
- 旧 `operations`/`filmOps` 字段保留一个兼容周期，仅用于展示或回放，不再作为页面唯一写入依据。
- 响应新增 `runId`、`status`、`toolCalls`、`plan`、`changed`、`applied`、`rev`、`issues`；前端按 README 的兼容项处理。

### 4.4 验收

修改过分镜或时间线后：

- 读取最新文档校验关键不变量；
- 时间线检查空轨、重叠、缺失媒体、锁定对象；
- 分镜检查空镜头、缺镜、失效候选；
- 验收失败时允许模型修正一次；仍失败则返回问题，不声称完成。

## 5. 多 Agent：Plan-Execute

### 5.1 新增 planner 工作槽

新增 `planner` 角色；其余六个角色（storyboard / material / edit / audio / qc / conversation）保留：

- `planner` 只生成计划，不直接写工程；默认计划在未绑定模型时仍可运行；
- 编排器（后端确定性组件）负责计划校验、依赖调度、步骤状态和提交/回滚；
- 计划由 `planner` 生成；planner 不可用或返回无效计划时，使用确定性五阶段计划；
- 简单目标仍可由 `conversation` 的 ReAct 循环直接处理；
- 计划对象写入运行记录，支持取消、失败重试和有限次重规划。

### 5.2 计划对象

```json
{
  "version": 1,
  "id": "plan_...",
  "goal": "生成 30 秒粗剪",
  "base": { "storyboard": 10, "timeline": "rev..." },
  "steps": [
    {
      "id": "generate",
      "role": "storyboard",
      "action": "generate_storyboard",
      "goal": "生成可执行分镜",
      "dependsOn": [],
      "input": {},
      "acceptance": ["shots > 0", "duration in range"],
      "status": "pending"
    },
    {
      "id": "query",
      "role": "material",
      "action": "plan_queries",
      "dependsOn": ["generate"],
      "status": "pending"
    },
    {
      "id": "match",
      "role": "material",
      "action": "match_storyboard",
      "dependsOn": ["query"],
      "status": "pending"
    },
    {
      "id": "verify",
      "role": "qc",
      "action": "validate_storyboard",
      "dependsOn": ["match"],
      "status": "pending"
    },
    {
      "id": "continuity",
      "role": "edit",
      "action": "handoff_storyboard",
      "dependsOn": ["verify"],
      "status": "pending"
    }
  ]
}
```

计划写入 `.film/agent-plan.json` 或运行记录，不依赖页面状态。

### 5.3 编排器

1. 校验计划：角色合法、依赖无环、步骤上限、写入权限、不能包含 render/export。
2. 把就绪步骤交给对应专业 Agent；专业 Agent 在自己的工具白名单内执行。
3. 每个步骤返回 artifact、`changed`、`issues`、`rev`。
4. 所有写操作串行；读取可并行。
5. 一个步骤失败：保留已完成步骤的结果，调用 `planner` 重规划，最多 2 次；不能自动重放已经成功写入的步骤。
6. 最终由 `qc` 做验收；失败保留已完成检查点，只重跑失败/未完成步骤。
7. 完成后写运行记录和撤销快照、通知页面；不自动渲染/导出。

### 5.4 与现有五阶段兼容

- 计划步骤 ID 优先映射现有 `generate`、`query`、`match`、`verify`、`continuity`，现有运行面板仍能显示。
- 新增 `fill`、`replan` 等内部步骤只出现在计划详情，不新增页面阶段 ID。
- 现有 `PIPELINE_STEPS` 保留；计划记录增加 `plan` 字段，旧运行文件可继续读取。

## 6. 每个 Agent 的工具需求

详细工具目录见 `TEMP/Agent工具接口文档.md` 的“目标工具目录”章节。所有角色都有项目级工作区工具（`workspace_list/read/write`、`run_code`）；原则：

- `planner`：读项目/分镜/时间线/脚本/能力，生成计划，不写工程。
- `storyboard`：读项目/脚本/素材，检索参考素材，生成/编辑/补镜/校验分镜。
- `material`：读分镜/脚本/字幕，语义检索、素材探测、看帧、匹配候选和覆盖报告。
- `edit`：读时间线/项目文件/脚本，编辑时间线、插入素材、音频/字幕/转场基础操作、预览、撤销。
- `audio`：读时间线/字幕/脚本，搜索/生成/分析音频，写入音频属性；当前仍停用。
- `qc`：读分镜/时间线/素材/音频/字幕，查看帧、分析响度、运行 QC、报告问题和修复建议；不写。
- `conversation`：读取、搜索、匹配、补镜、编辑分镜/时间线、QC、预览、撤销；不渲染/导出。
- MCP/外部 Agent：与内置 Agent 共用工具实现，按交接阶段裁剪；补齐 match/fill/handoff 等粗剪工具。

## 7. 实施顺序

1. 统一 ToolRegistry，把现有 `agent-tools` 的读写函数注册进去。
2. 给 `callAgent` 增加工具循环所需的 messages/tool result 支持和预算；保留 JSON 兼容。
3. 先接 conversation 的读/写/搜索/QC/undo/preview，完成 ReAct。
4. 增加分步检查点、失败重试和连续性撤销快照。
5. 增加 planner 工作槽和 Plan schema；粗剪流水线改为编排器计划执行，planner 无模型时使用默认计划。
6. 补齐 `match_storyboard`、`fill_storyboard`、`handoff_storyboard` 等工具，并让 MCP 与内置复用。
7. 最后接音频/生成类工具；不在首期开放 render/export。

## 8. 与 ChatCut / OpenFilm 原项目的对标边界

### 8.1 首期覆盖（P0/P1）

- ReAct 工具循环、工具结果差分、分步检查点、失败重试、写入后验收。
- Plan-Execute 的计划、依赖、步骤状态、失败重规划和最终 QC。
- 项目/分镜/时间线/文件/脚本/字幕/转写的读取。
- 分镜生成、结构编辑、匹配、补镜、校验、交接。
- 时间线原生 `applyOps`：片段、轨道、转场、音量、淡入淡出、字幕基础操作。
- 素材语义检索、外部素材检索与导入、媒体探测、素材/时间线抽帧。
- 本地/网络音频、TTS、配乐、音效、字幕、响度/波形分析和音频落轨（音频 Agent）。
- 计划追问、停止/重试、项目级分阶段记忆、工具结果工件。

### 8.2 暂不纳入首期（P2）

这些是 ChatCut 有、但 OpenFilm 当前模型/页面不具备明确承载的类别，先不伪装成已支持：

- 高级视觉：特效、调色、自动重构、布局、动态图形、模板库和 shader。
- 多机位、link group、多时间线/版本管理、项目创建/删除。
- 技能安装/执行、任意代码执行、网页浏览/爬取。
- 生成类 `submit_image` / `submit_video` / `submit_voice` / `submit_music` / `submit_sound` 的完整产品化；首期只保留 `fill_storyboard` 的显式生成模式和音频阶段预留。
- 导出、渲染、发布：明确禁止 Agent 调用，仍由用户从 Studio 导出中心触发。

### 8.3 兼容原则

- `edit_timeline` 一个工具覆盖全部原生时间线操作，不按 ChatCut 的颗粒度拆成第二套编辑 API。
- 新增工具名可以不同，但执行仍落到 OpenFilm 的 storyboard/film/audio/caption 文档；不能复制 ChatCut 的 EditorCore。
- 优先补“AI 对话和粗剪必需”的读取、匹配、补镜、交接、QC、撤销和工件读取；高级视觉工具单独评审。

## 9. 风险与取舍

- provider 是否支持原生工具调用不一致：必须有 JSON 动作回退，否则 ReAct 只对部分模型可用。
- 工具结果过大：必须先做摘要/引用，否则上下文会迅速爆炸。
- 草稿提交会增加实现复杂度：但比让模型直接反复写 `film.html` 更可控。
- 计划质量依赖 planner：必须做确定性的 DAG/权限/预算校验，不能把模型输出当作可执行真值。
- 自动验收会增加模型调用：只对发生写入的运行执行，且限制轮数。

## 10. 前端配合

前端需要配合的内容只写入 `TEMP/README.md` 的前端章节，包括：

- 展示 ReAct 的工具调用、运行状态、停止/重试和最终变更；
- 展示 Plan-Execute 的计划步骤、角色、依赖、进度和失败原因；
- 适配 `applied`/`changed`/`rev`，避免页面再次应用已经由服务端提交的操作；
- 设置页显示新增的 planner 卡；未绑定模型时仍显示默认计划状态，工具权限/工具目录展示沿用现有 Agent 设置。

本轮不修改前端代码。
